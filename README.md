# Pavepal AI Chatbot (Gemini + Hybrid Retrieval)

This project builds a grounded AI assistant for pavement maintenance decisions using:

- Structured inspection data from JSON (road segments + location-level defects)
- Unstructured guidance from PDF manuals
- Gemini API for embeddings and answer generation
- Hybrid retrieval (dense semantic + sparse TF-IDF), explicitly **not BM25**
- A simple Streamlit chat UI with source transparency

## 1. What This App Does

Pavepal answers natural-language questions such as:

- Which roads look highest maintenance priority and why?
- What defect patterns are visible on a specific road?
- What actions are suggested by both inspection evidence and manual guidance?

It retrieves relevant context from both structured and unstructured sources, then asks Gemini to generate a grounded response with citations.

## 5. How Hybrid Retrieval Works

The retriever combines two signals:

1. Dense semantic similarity
- Embeddings generated by Gemini (`models/text-embedding-004` by default, configurable via `GEMINI_EMBEDDING_MODEL`)
- Captures semantic meaning and paraphrases

2. Sparse lexical similarity
- TF-IDF vectors over all document chunks
- Captures exact road names, defect terms, and domain keywords

Final score:

$$
\text{hybrid}(d, q) = \alpha \cdot s_{dense}(d, q) + (1-\alpha) \cdot s_{sparse}(d, q)
$$

Where `alpha` is adjustable in the UI sidebar.

## 6. Data Ingestion

- `roadSegments (2).json`: Each feature becomes a road-level summary document
- `locations (2).json`: Each feature becomes a location-level defect observation document
- PDF files in `data/`: Text extracted page-by-page and split into overlapping chunks

All chunks are indexed together so one query can retrieve evidence from both data and guidance.

## 7. Trust, Grounding, and Transparency

- Responses are prompted to use only retrieved context
- If context is insufficient, assistant should say what is missing
- UI exposes source chunks, scores, and metadata for inspection

## 8. Notes and Limitations

- This is a decision-support tool, not a substitute for licensed engineering judgment
- PDF text quality depends on extractability (scanned PDFs may need OCR)
- For production use, add:
  - Persistent vector store (e.g., FAISS/pgvector)
  - Authentication and audit logs
  - Evaluation set + retrieval/answer quality metrics
  - Guardrails/policies for high-stakes recommendations

## 9. Evaluation Framework (Capstone-Aligned)

This project now includes a research-oriented retrieval evaluation pipeline aligned with:
"Grounded AI for Road Maintenance Decisions: Evaluating Retrieval Quality and Failure Modes."

### 9.1 Components

- `evaluation/benchmark_queries.json`: Representative decision-support queries with expected sources, road targets, and keywords.
- `src/pavepal/eval_framework.py`: Offline-capable evaluator that runs retrieval only and computes:
  - Precision@k
  - Recall@k
  - MRR (Mean Reciprocal Rank)
  - nDCG@k
- Failure mode tagging per query:
  - `no_relevant_retrieval`
  - `missing_structured_evidence`
  - `missing_manual_evidence`
  - `conflicting_condition_signals`
  - `low_retrieval_confidence_gap`
- `run_evaluation.py`: One-command entry point that writes:
  - `evaluation/outputs/retrieval_eval.json`
  - `evaluation/outputs/retrieval_eval.md`

### 9.2 Run Evaluation

```bash
python run_evaluation.py
```

Optional parameters:

```bash
python run_evaluation.py --top-k 8 --alpha 0.65
```

The evaluator intentionally uses sparse retrieval only (stable/offline mode) so evaluation still runs when embedding APIs are unavailable or quota-limited.

### 9.3 Architecture Summary

1. Data ingestion
- Structured: `roadSegments (2).json`, `locations (2).json`
- Unstructured: PDF manuals in `data/`

2. Retrieval pipeline
- HybridRetriever combines dense + TF-IDF when embeddings are available
- Automatic fallback to sparse-only retrieval if embeddings fail

3. Grounded answering
- Prompt constrains answer generation to retrieved evidence with citations
- Quota/API failures trigger an extractive fallback answer

4. Evaluation pipeline
- Benchmark queries define expected evidence targets
- Retriever outputs are scored quantitatively and tagged with failure modes
- JSON + Markdown reports support technical reporting and reproducibility
